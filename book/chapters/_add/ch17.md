## Deep dive: Excel as an interface, not a database

Finance teams will always use Excel, and a well-made workbook is a perfectly good integration interface. The trouble starts when a workbook is treated as a trusted data source. This section covers the rules that keep Excel exports useful and Excel imports safe.

### Export: make the file self-explanatory

A file outlives the conversation in which it was requested. Every export Harbourline produces carries:

- **A title row** stating what the data is and for which period (`Harbourline invoices – 2026-09`).
- **An Excel table** (`InvoiceTable`) rather than a plain range, so filters, sorting and structured references work, and the data range grows when users add formulas next to it.
- **Real numbers and dates**, formatted with number formats (`#,##0.00`, `yyyy-mm-dd`) instead of text that looks like numbers. Text "numbers" can't be summed, and they're the most common complaint about generated spreadsheets.
- **Frozen header rows**, so headers stay visible on long sheets.

Avoid merged cells, colours that carry meaning without a legend, and hidden sheets used for "internal" data: someone will unhide them.

### Formula injection

When an export contains text that users or partners typed, a value beginning with `=`, `+`, `-` or `@` can be interpreted as a formula by spreadsheet programs. That's known as CSV or formula injection. For `.xlsx` files written with a library such as ClosedXML, setting a cell's value to a string stores it as text, not as a formula, so the risk is mainly with CSV exports. If you also produce CSV, prefix such values with an apostrophe or reject them at input.

### Import: never trust the sheet

Every uploaded workbook is untrusted input, whoever uploads it. The import in this chapter applies four defences:

::: {#tbl:importchecks caption="Checks applied to an uploaded workbook"}
| Check | Where | Why |
|---|---|---|
| Size limit (5 MB) | Function, before reading | A huge or zip-bombed file can exhaust memory |
| Is it a workbook? | `PriceImport.Read` | A renamed file or corrupt upload gets a clean 400 |
| Expected sheet and columns | `PriceImport.Read` | Users rename sheets and insert columns |
| Every value validated | Per row, with row and column in the error | Sheet protection and data validation are conveniences, not controls |
:::

The last row of the table is the important one. **Sheet protection** in Excel is easy to remove, and **data validation** only checks values typed into a cell, not values pasted or produced by another program. The template's protection and validation help honest users make fewer mistakes; the server-side validation is what actually protects Dataverse.

### Partial success, reported clearly

The import applies valid rows and reports invalid ones with their sheet row and column, rather than rejecting the whole file for one bad cell. Finance asked for that behaviour: a 300-row price review shouldn't be blocked by one typo. The response says how many rows were applied and lists each error, so the user can fix and re-upload only the failed rows. Because the update is idempotent (setting a rent to a value), re-uploading the whole file is also safe.

When partial success is **not** acceptable, for example for a set of journal lines that must balance, validate everything first and apply nothing unless all rows pass. Choose deliberately, and write the choice in the user documentation.

### Large files and memory

ClosedXML builds the whole workbook in memory, which is convenient up to tens of thousands of rows. Step 4's streaming writer, using the Open XML SDK's `OpenXmlWriter`, writes rows one at a time and keeps memory flat for much larger extracts. Both libraries are MIT-licensed, which is why this book uses them; some popular Excel libraries need a commercial licence for business use, so check before you add one.

## Guided lab: round-trip a price review

**Requires:** the host running locally with Dataverse configured, some invoices for September 2026 (the invoice sync from Chapter 10 creates them from the mock), and Excel or another spreadsheet program that opens `.xlsx` files.

### Lab 17.1 – Export a month

```bash
curl -s -o invoices-2026-09.xlsx -w "%{http_code} %{content_type}\n" \
  http://localhost:7071/api/v1/finance/invoices/2026-09
```

**Expected output:**

```text
200 application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
```

Open the file. **Checkpoint:** a title in A1, the header in row 3 with filter buttons, amounts right-aligned with two decimals, and rows 1–3 frozen. Type `=SUM(` under the Amount column and select the amounts: the sum works, because the amounts are numbers, not text.

### Lab 17.2 – Ask for a bad month

```bash
curl -s http://localhost:7071/api/v1/finance/invoices/September
```

**Checkpoint:** a 400 problem response with the title *Invalid month* and the hint *Use the form yyyy-MM, for example 2026-09.*

### Lab 17.3 – Prepare an upload

Create a new workbook with one sheet named **Prices**. In row 1 put the headers `Property code`, `Current rent`, `New rent`. Add these rows (use codes that exist in your environment for the first two):

| A | B | C |
|---|---|---|
| HBR-0042 | 1250 | 1295 |
| HBR-0043 | 985.5 | |
| HBR-0051 | 2100 | twelve hundred |
| HBR-9999 | 500 | 550 |
| BAD | 0 | 100 |

Save it as `prices-lab.xlsx`. (The unit tests in `tests/Harbourline.Connect.UnitTests/Excel/ExcelTests.cs` generate the protected template from Step 5; this hand-made file deliberately skips that protection, which is exactly what a determined user could do.)

### Lab 17.4 – Upload it

```bash
curl -s -X POST http://localhost:7071/api/v1/finance/prices \
  -H "Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet" \
  --data-binary @prices-lab.xlsx | jq
```

**Expected output** (illustrative):

```json
{
  "applied": 1,
  "errors": [
    { "row": 4, "column": "C", "message": "New rent must be a number from 1 to 100000." },
    { "row": 6, "column": "A", "message": "'BAD' is not a property code." },
    { "row": 5, "column": "A", "message": "Property HBR-9999 does not exist." }
  ]
}
```

**Checkpoint:** one row applied (`HBR-0042` now has a rent of 1,295), the empty *New rent* on row 3 was skipped silently, and every problem names its row and column. Nothing about the bad rows reached Dataverse.

### Lab 17.5 – Send something that isn't a workbook

```bash
echo "hello" > not-a-workbook.xlsx
curl -s -X POST http://localhost:7071/api/v1/finance/prices --data-binary @not-a-workbook.xlsx
```

**Checkpoint:** a 400 response with the title *Not an Excel workbook*. A renamed text file can't crash the import.

### Lab 17.6 – Fix and re-upload

Correct row 4 to `1200`, delete rows 5 and 6, and upload again. **Checkpoint:** `applied` is 2 and `errors` is empty. `HBR-0042` was set to 1,295 again; setting a value twice is harmless.
